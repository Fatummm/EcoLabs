## 1. Алгоритм

В задаче требуется реализовать структуру данных *k-мерного дерева* (KD-tree) — пространственное дерево поиска, предназначенное для эффективного решения задачи поиска ближайших соседей в многомерном пространстве.

KD-дерево представляет собой двоичное дерево, в котором каждый узел разбивает пространство гиперплоскостью, перпендикулярной одной из координатных осей. Ось разбиения чередуется на каждом уровне глубины дерева по формуле:

```
axis = depth % dimension
```

где `dimension` — размерность пространства. Например, для трёхмерного случая (`dimension = 3`) корень разбивает по оси X, его дети по оси Y, их дети по оси Z, затем снова X и так далее.

Каждый узел хранит одну точку. Все точки с меньшим значением координаты по текущей оси разбиения находятся в левом поддереве, все с большим или равным — в правом.

Построение дерева происходит рекурсивно: на каждом шаге среди точек диапазона находится *медиана* по текущей оси разбиения, она становится узлом, а оставшиеся точки рекурсивно распределяются по левому и правому поддеревьям. Выбор медианы обеспечивает сбалансированность дерева при построении.

Поиск *k ближайших соседей* выполняется рекурсивным обходом дерева с отсечением (backtracking). Алгоритм сначала спускается в ближайшее к запросу поддерево, а затем проверяет, может ли в другом поддереве быть точка ближе, чем самый далёкий из уже найденных соседей. Если расстояние от точки запроса до разделяющей гиперплоскости меньше расстояния до текущего худшего соседа, второе поддерево тоже обходится. В противном случае целое поддерево отсекается, что и обеспечивает эффективность поиска.

## 2. Асимптотика

**Построение дерева.** На каждом уровне рекурсии выполняется поиск медианы с помощью алгоритма QuickSelect, который работает за O(n) в среднем. Поскольку на каждом уровне суммарное число обрабатываемых точек равно n, а уровней — O(log n) при выборе медианы, общая сложность построения составляет **O(n log n)** в среднем.

**Поиск k ближайших соседей.** В среднем случае, при сбалансированном дереве, поиск имеет сложность **O(log n)**, так как отсечение поддеревьев позволяет обойти лишь небольшую часть узлов. Однако в наихудшем случае (вырожденное дерево или неудачное расположение точек) сложность может деградировать до O(n) — когда невозможно отсечь ни одно поддерево и приходится обходить все узлы.

**Вставка точки.** Вставка выполняется аналогично поиску: рекурсивный спуск по дереву до листа, куда добавляется новый узел. Средняя сложность — **O(log n)**, наихудшая — O(n) для вырожденного дерева.

**Удаление точки.** Удаление из KD-дерева — нетривиальная операция. При удалении узла с потомками необходимо найти замену — узел с минимальной координатой по текущей оси разбиения в соответствующем поддереве. Поиск минимума в поддереве имеет сложность O(n) в наихудшем случае, так как минимум по нецелевой оси может находиться в любом из поддеревьев. Средняя сложность удаления — **O(log n)**.

**Память.** Пространственная сложность составляет **O(n)** — по одному узлу на каждую точку, каждый узел хранит копию координат и два указателя на дочерние узлы.

| Операция | Среднее | Наихудшее |
|---|---|---|
| Построение | O(n log n) | O(n log n) |
| Поиск k ближайших | O(log n) | O(n) |
| Вставка | O(log n) | O(n) |
| Удаление | O(log n) | O(n) |
| Память | O(n) | O(n) |

## 3. Выбор подхода

### Поддержка нескольких типов координат

В реализации поддерживается пять типов координат: `int16_t`, `int`, `int64_t`, `float` и `double`. Они определены в файле `KDTreeTypes.h` как константы:

```c
#define KD_TYPE_INT16       0   /* int16_t   */
#define KD_TYPE_INT         1   /* int       */
#define KD_TYPE_LONGLONG    2   /* int64_t   */
#define KD_TYPE_FLOAT       3   /* float     */
#define KD_TYPE_DOUBLE      4   /* double    */
```

Точка представлена структурой `KDPoint`, содержащей нетипизированный указатель `void*` на массив координат. Все операции сравнения и вычисления расстояний реализованы через вспомогательные функции с `switch` по типу координат (`CKD_Tree_AxisLess`, `CKD_Tree_AxisEqual`, `CKD_Tree_AxisDiff`). Такой подход позволяет использовать одну и ту же рекурсивную логику для всех типов, а конкретный тип задаётся при вызове `BuildTree*` и сохраняется в поле `m_type` компонента.

### Алгоритм QuickSelect для нахождения медианы

При построении дерева критически важно находить медианный элемент по текущей оси разбиения для обеспечения сбалансированности. Наивный подход — сортировка массива на каждом уровне — имеет сложность O(n log n) на уровень, что приводит к суммарной сложности O(n log²n).

Вместо этого используется алгоритм *QuickSelect*, который находит k-й элемент в неотсортированном массиве за O(n) в среднем. Он работает аналогично быстрой сортировке, но рекурсивно обрабатывает лишь одну из двух частей массива после разбиения. В качестве опорного элемента выбирается центральный элемент диапазона:

```c
/* Choose pivot at middle */
pivot_idx = left + (right - left) / 2;
pivot = points[pivot_idx];
```

Благодаря этому суммарная сложность построения дерева составляет O(n log n) вместо O(n log²n).

### Использование квадрата евклидова расстояния

Для поиска ближайших соседей используется *квадрат* евклидова расстояния вместо самого расстояния. Поскольку квадратный корень — монотонная функция, порядок точек по расстоянию сохраняется, а вычисление `sqrt` не требуется:

```c
static double CKD_Tree_SquaredDistance(
    voidptr_t coords1,
    voidptr_t coords2,
    uint16_t dimension,
    int16_t type)
{
    double dist = 0.0;
    uint16_t i;
    double diff;

    for (i = 0; i < dimension; i++) {
        diff = CKD_Tree_AxisDiff(coords1, coords2, (int16_t)i, type);
        dist += diff * diff;
    }

    return dist;
}
```

Вычисление разности координат для целочисленных типов выполняется в более широком типе (`int64_t`), чтобы избежать переполнения при вычитании.

### Удаление узла

Удаление из KD-дерева сложнее, чем из обычного BST, поскольку замена удалённого узла должна учитывать ось разбиения этого узла. Используется стандартный алгоритм: при удалении узла с правым поддеревом выполняется поиск узла с *минимальной* координатой по оси разбиения удаляемого узла в правом поддереве, затем координаты копируются в удаляемый узел, а замена рекурсивно удаляется. Если правого поддерева нет, но есть левое, оно перемещается на место правого и аналогично обрабатывается.

## 4. Функции

Интерфейс `IKD_Tree` определён в файле `IKD_Tree.h` и наследует от `IEcoUnknown` (методы `QueryInterface`, `AddRef`, `Release`). Интерфейс предоставляет следующие методы:

### BuildTree / BuildTree*

```c
int16_t ECOCALLMETHOD BuildTree(
    /* in */ IKD_TreePtr_t me,
    /* in */ KDPointPtr_t* points,
    /* in */ int32_t count,
    /* in */ uint16_t dimension
);
```

Строит KD-дерево из массива точек `points` размером `count`, каждая точка имеет `dimension` координат. Массив может быть переупорядочен в процессе построения (QuickSelect переставляет элементы на месте). Если дерево уже было построено, оно предварительно уничтожается.

Помимо базовой версии `BuildTree` (для `int16_t`), реализованы типизированные варианты:

- `BuildTreeInt` — координаты типа `int`
- `BuildTreeLongLong` — координаты типа `int64_t`
- `BuildTreeFloat` — координаты типа `float`
- `BuildTreeDouble` — координаты типа `double`

Все варианты вызывают общую внутреннюю функцию `CKD_Tree_BuildTreeTyped`, передавая ей соответствующий `KD_TYPE_*`. В случае ошибки выделения памяти частично построенное дерево корректно освобождается, а функция возвращает `ERR_ECO_OUTOFMEMORY`.

### SearchKNearest

```c
int16_t ECOCALLMETHOD SearchKNearest(
    /* in  */ IKD_TreePtr_t me,
    /* in  */ KDPointPtr_t point,
    /* in  */ int16_t k,
    /* out */ KDSearchResult* result
);
```

Выполняет поиск `k` ближайших соседей к данной точке. Координаты точки запроса должны иметь тот же тип, с которым было построено дерево. Результат содержит указатели на найденные точки (во внутренних узлах дерева) и квадраты евклидовых расстояний до них. Массивы результата выделяются внутри функции; их освобождение — ответственность вызывающего кода. Порядок точек в результате *не гарантирован* (не отсортирован по расстоянию).

### InsertPoint

```c
int16_t ECOCALLMETHOD InsertPoint(
    /* in */ IKD_TreePtr_t me,
    /* in */ KDPointPtr_t point
);
```

Вставляет одну точку в существующее дерево. Дерево должно быть предварительно построено одним из методов `BuildTree*`. Вставка выполняется рекурсивным спуском по дереву: на каждом уровне сравнивается координата вставляемой точки с координатой узла по текущей оси разбиения, и спуск продолжается в соответствующее поддерево. Новый узел создаётся на позиции пустого указателя.

Следует учитывать, что многократные вставки без перестроения могут привести к разбалансировке дерева.

### DeletePoint

```c
int16_t ECOCALLMETHOD DeletePoint(
    /* in */ IKD_TreePtr_t me,
    /* in */ KDPointPtr_t point
);
```

Удаляет точку с совпадающими координатами из дерева. Если такой точки нет, дерево остаётся без изменений. Алгоритм удаления описан в разделе «Выбор подхода». Если в дереве есть несколько точек с одинаковыми координатами, при равенстве по оси разбиения поиск продолжается и в левом поддереве, чтобы корректно найти нужную точку (медианный алгоритм построения может поместить равные по оси точки в любое из поддеревьев).

### DestroyTree

```c
int16_t ECOCALLMETHOD DestroyTree(
    /* in */ IKD_TreePtr_t me
);
```

Рекурсивно освобождает все узлы дерева (обход в обратном порядке, post-order), сбрасывает внутреннее состояние компонента (размерность, счётчик точек, тип координат). После вызова `DestroyTree` дерево можно построить заново.

## 5. Результаты тестирования

Тесты реализованы в файле `CKD_Tree_Test.c`. Каждый тест является самодостаточным: создаёт свой экземпляр компонента, генерирует данные, строит дерево, выполняет проверки и полностью освобождает все ресурсы. Тесты можно запускать в любом порядке. Возврат 0 означает успех.

### Структура каждого теста

Каждый тест выполняет 5 шагов:

1. **Построение дерева** — вызов соответствующего `BuildTree*` и проверка, что число точек в дереве совпадает с ожидаемым.
2. **Поиск k ближайших соседей** — для 5 случайных запросов результат `SearchKNearest` сравнивается с *brute-force* эталоном. Эталонный поиск перебирает все точки и возвращает k наименьших квадратов расстояний в отсортированном порядке. Компонент возвращает соседей в произвольном порядке, поэтому перед сравнением они сортируются по расстоянию.
3. **Вставка точки** — последняя точка запроса вставляется в дерево, после чего проверяется, что она стала собственным ближайшим соседом (расстояние = 0) и что счётчик точек увеличился.
4. **Удаление точки** — вставленная точка удаляется, после чего повторный поиск ближайших соседей должен совпасть с результатом до вставки.
5. **Уничтожение и освобождение** — вызов `DestroyTree` и `Release`, проверка, что счётчик ссылок стал нулевым.

Каждый 100-й запрос дополнительно сверяется с brute-force эталоном. Сам тест не замеряет время — для измерения производительности предполагается использование внешних инструментов. Основная цель теста — убедиться в корректности поиска при большом объёме данных и множестве запросов.

### Генерация данных

Тестовые данные генерируются детерминированным линейным конгруэнтным генератором (LCG):

```c
static int32_t CKD_Tree_Test_Random(uint32_t* pSeed, int32_t range) {
    *pSeed = (*pSeed * 1103515245UL + 12345UL) & 0x7FFFFFFFUL;
    return (int32_t)((*pSeed >> 8) % (uint32_t)range) - range / 2;
}
```

Начальное значение (seed) зависит от типа координат и количества точек, поэтому каждый тест имеет свою уникальную, но воспроизводимую последовательность данных. Для целочисленных типов `int64_t` значения масштабируются за пределы 32-битного диапазона (умножением на 100 000), для `float` и `double` добавляется дробная часть.

### Демонстрация в EcoMain

Помимо автоматических тестов, файл `Lab1.c` содержит точку входа `EcoMain`, которая демонстрирует работу компонента на 15 точках типа `int64_t` с размерностью 3. Демонстрация включает:

- Вывод входных точек
- Построение дерева методом `BuildTreeLongLong`
- Печать структуры дерева (рекурсивная функция `PrintTree` выводит каждый узел с отступом по глубине и указанием оси разбиения)
- Поиск 4 ближайших соседей к точке (45, 50, 40) с выводом результатов
- Уничтожение дерева
- Запуск всех 12 тестов с итоговым подсчётом неуспешных

Тестовые данные специально включают экстремальные значения (−5 000 000 000 и +9 000 000 000), чтобы проверить корректность работы с большими числами типа `int64_t`.


## 6. Использование ИИ
В процессе выполнения лабораторной работы использовалась модель искусственного интеллекта Claude Opus 4.6
Результаты и выводы использования ИИ-модели:
1. **Галлюцинация и потеря контекста.** На этапе планирования и построения архитектуры модель решила использовать QuickSort для поиска медианы вместо QuickSelect. Ключевое отличие данных двух алгоритмов в контексте моей задачи заключается в том, что QuickSort запускается рекурсивно от двух получившихся частей массива, что по мастер-теореме(рекурсивные функции) выдаёт итоговую асимптотическую сложность O(nlogn). В свою очередь QuickSelect в среднем работает за линейное время(O(2n) = O(n)).
2. **Удобные оптимизации.** Моделью была предложено использование аналога перечисления или битмаски для использования методов к-мерного дерева для разных типов. Данная оптимизация упрощает написание кода, делает его универсальным и уменьшает дублирование кода посредством внедрения небольшого количества вспомогательных функций

В остальном нейросеть показала достаточно хорошие результаты как со стороны генерации экспериментального кода, так и со стороны системного архитектора
