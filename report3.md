## 1. Алгоритм

В лабораторной работе №3 компонент `CKD_Tree` из первой работы дополнен исходящим интерфейсом `IKD_TreeEvents`. Клиент получает уведомления во время построения дерева и поиска ближайших соседей.

При построении на каждом шаге QuickSelect находит медиану диапазона по текущей оси. После создания узла приходит событие `OnBuildNode` с границами диапазона, индексом медианы и осью разбиения. Затем обрабатываются оба поддерева.

При поиске `OnSearchVisit` приходит после вычисления квадрата расстояния и обновления набора кандидатов. Алгоритм сначала обходит ближнее поддерево. Если набор уже содержит `k` кандидатов и квадрат расстояния до разделяющей плоскости не меньше квадрата расстояния до худшего кандидата, дальнее поддерево можно отсечь. Для каждого такого непустого поддерева приходит `OnSearchPrune`.

## 2. Точки подключения

### Контейнер, точка подключения и приёмник

Каждый экземпляр дерева имеет собственную точку подключения для `IKD_TreeEvents`. Клиент получает контейнер через `QueryInterface`, находит точку по IID событий и подписывает приёмник вызовом `Advise`. Обратный вызов получает указатель на источник, поэтому один приёмник различает несколько деревьев. Идентификатор подписки (`cookie`) хранится для каждой пары «точка подключения — приёмник».

Точка подключения хранит сильные ссылки на приёмники в `Eco.List1`. Перечислитель создаёт снимок подписок отдельно для каждого события. Изменение подписок из обработчика применяется при рассылке следующего события. Обратные вызовы выполняются синхронно. Ошибка отдельного обработчика или невозможность создать снимок не прерывает вычисление. Повторный запуск операции на том же дереве из обработчика отклоняется, пока идёт рассылка.

Контейнер использует общий счётчик ссылок с `IKD_Tree`. Схема поиска точки и подписки соответствует лекции №5.

## 3. Функции

| Интерфейс | Методы | Назначение |
|---|---|---|
| `IKD_TreeEvents` | `OnBuildNode`, `OnSearchVisit`, `OnSearchPrune` | Получение шагов построения и поиска |
| `IEcoConnectionPointContainer` | `FindConnectionPoint`, `EnumConnectionPoints` | Поиск точки по IID событий и перечисление точек компонента |
| `IEcoConnectionPoint` | `Advise`, `Unadvise`, `EnumConnections` | Подписка, отключение по `cookie` и перечисление подключений |
| `IEcoConnectionPoint` | `GetConnectionInterface`, `GetConnectionPointContainer` | Получение IID исходящего интерфейса и контейнера точки |
| `IEcoEnumConnectionPoints`, `IEcoEnumConnections` | `Next`, `Skip`, `Reset`, `Clone` | Обход точек и подписок |

Интерфейс событий находится в `SharedFiles/IKD_TreeEvents.h`. Точка подключения и перечислители расположены в `HeaderFiles` и `SourceFiles`. Приёмники и сценарии подписки находятся в `UnitTestFiles/CKD_Tree_EventsTest.c`.

## 4. Результаты тестирования

### Набор тестов

Клиент создаёт через интерфейсную шину два экземпляра `CKD_Tree` и два приёмника. В каждом прогоне дерево строится по семи двумерным точкам. Для запроса `(6, 0)` при `k = 1` ожидается точка `(6, 0)` с квадратом расстояния 0. На каждую активную подписку приходится 7 событий создания узла, 3 события посещения и 2 события отсечения.

| Сценарий | Проверка | Результат |
|---|---|---|
| Один ко многим | Дерево A отправляет события обоим приёмникам | PASS |
| Многие к одному | Деревья A и B отправляют события только приёмнику 1 | PASS |
| Многие ко многим | Оба дерева отправляют события обоим приёмникам | PASS |
| Отключение | После `Unadvise` события от A получает только приёмник 2, от B — только приёмник 1 | PASS |
| Исходные тесты KD-дерева | 12 сценариев первой работы, включая пять типов координат и 10 000 запросов | 12 из 12 |

Пример вывода клиента для первого приёмника.

```text
Sink 1 / Tree A / Step 1: build [0, 7), median 3, axis 0
Sink 1 / Tree A / Step 8: visit, axis 0, distance^2 36, candidates 1
Sink 1 / Tree A / Step 12: prune, axis 0, plane^2 36, worst^2 0
```

Тесты прошли на стенде с тестовыми реализациями шины, распределителя памяти, `Eco.List1` и `Eco.StdIO.C89`. Проверки выделенной памяти и счётчиков ссылок также прошли.

### Вывод

Два экземпляра дерева независимо управляют подписками и передают несколько видов событий. Тип связи определяется подключениями клиента. В тестах изменение схемы подписки меняло получателей событий и сохраняло результат поиска ближайшего соседа.
